Help

Everything you need to go from sign-up to your first verdict. The full documentation has every detail.

Get started

  1. Sign up at app.tracetells.com. Your account comes with its first website.
  2. Add the tag to every page, before </head>. Setup › Get started shows it with your website's key. The first visit ticks the step off.
  3. Say what success means in a trace.json in your repository: the events your app sends, your goals, funnels and product areas. In Claude Code, /trace:setup writes it for you.
  4. Analyse once Home says it's time, with /trace:analyse in your coding agent or Analyse here in the dashboard. Pick the insights worth doing, ship one, mark it released, and Trace gives a verdict on its goal.

The tag

<script src="https://app.tracetells.com/d.js?k=YOUR_KEY" data-key="YOUR_KEY" defer></script>
  • Single-page apps are followed on their own (History and Navigation API, hash routers). Dynamic paths group into routes like /products/:id; name the ones that don't with data-routes="/products/:slug".
  • Custom events: trace.track("signup", { plan: "pro" }), or without JavaScript, data-trace-event="signup" on a button, link or form.
  • Signed-in people: call trace.identify(id) on every page with an id that isn't an email, ideally a keyed hash of the user's id. It's what DAU, MAU and retention count.
  • Hide what a page shows: data-trace-mask on an element keeps its text out entirely.
  • Consent: nothing is stored on visitors' devices, so no banner is needed. If your policy is to load nothing before consent, add data-consent="required" and call trace.consent(true) from your consent tool.

Every install option

trace.json

Goals live in code, next to the events that feed them, and the dashboard only shows results. Validate with trace check, apply with trace push, ideally from CI on every merge.

{
  "events": { "purchase": "Payment succeeded" },
  "kpis": {
    "checkout_conversion": {
      "conversion": { "from": { "pageview": "/checkout" }, "to": { "event": "purchase" } },
      "goal": "increase", "target": "55%"
    }
  },
  "funnels": { "buying": { "steps": [{ "pageview": "/cart" }, { "pageview": "/checkout" }, { "event": "purchase" }] } },
  "areas": { "checkout": { "name": "Checkout", "match": [{ "pageview": "/checkout*" }] } },
  "audience": { "marketing": ["/", "/pricing"], "engaged": [{ "event": "purchase" }] }
}
trace check
trace push trace.json --server https://app.tracetells.com --token $TRACE_TOKEN

Create the token under Account. Goals are matched by key, so renaming one keeps its history.

Your coding agent

Trace is an MCP server. In Claude Code, the plugin connects it and adds three commands:

/plugin marketplace add dobrinov/tracetells
/plugin install trace@tracetells
  • Then run /mcp, choose plugin:trace:trace and Authenticate. Your browser opens Trace to approve it; there's no token to copy.
  • /trace:setup adds the tag and writes trace.json from your code. /trace:analyse finds what to fix (add an area's key to look at one part of the product). /trace:fix implements an insight.
  • Other MCP clients connect to https://app.tracetells.com/mcp and sign in the same way.
  • Your agent sees the same aggregated summaries as the dashboard, never sessions or people, and analyses with its own model.

Privacy

  • Never collected: input values, page titles, query strings, page content, recordings.
  • Scrubbed twice: emails, cards, IBANs, tokens and phone numbers are removed in the browser and again on the server.
  • Cookieless: visits are told apart with a hash that changes every day and can't be traced back.
  • Your rules: admins mask elements, ignore pages, redact patterns and drop fields per website, under Setup › Privacy.
  • Your own machine: once your website is live, visits from localhost and private addresses are left out.

Performance

The collector is 8.3 KB on the wire, about 3 µs of work per click and no layout reads on the hot path. It takes notes while the page is busy and does its work when the browser is idle; if it ever fails, your site carries on as if it weren't there.

Self-hosting

The community edition is the same product, free and open source, with no limits on your own server: one Rust binary, SQLite to try it and Postgres for production.

trace init && trace serve
